The machinery — automated where it can be, gated where it cannot

WinA is built as a small, auditable pipeline: verified data in data/, a generator (scripts/build_site.py), and a gate (scripts/check_site.py) that must pass before anything is pushed. Human decisions — scope, intent, paths — are never automated; they sit on the review page and the questions list.

The pipeline

  1. Intake — submitted link + observed redirect + date + source, stored in separate intent/observed fields (data/intent-record inside data/products.json).
  2. Verify — fetch the official listing; record title, price, availability, browse node against a source ID in data/sources.json. Unconfirmable values stay blank + flagged.
  3. Render — generator emits pages, sitemap, feed, search index from the data; no hand-copied numbers.
  4. Gate — checker enforces disclosure, sponsored links, source coverage, link integrity, sitemap/feed coverage, data↔page sync. Exit code non-zero = no push.
  5. Measure — five events via the privacy-preserving counter; ledger rows only from authorized first-party reports.

The five events (recorded, privacy-preserving)

FLG-009: no canonical event list existed in the repository; this documented set is the adopted five — replace only on owner confirmation (Q-12). No cookies, no IPs, no fingerprinting; Do Not Track short-circuits everything.

page_view

denominator for every later ratio (views → clicks)

Trigger: any page load · payload: path, referrer_host, ts

outbound_click

measures interest leaving the site (not just affiliate links)

Trigger: click on any external link · payload: path, host, ts

affiliate_click

the outbound-click counter the brief asks for, scoped to monetized links

Trigger: click on a product link carrying the tracking tag · payload: path, product_id, ts

search_query

demand signal from readers; queries themselves are not stored (only length) to stay privacy-preserving

Trigger: site search submitted · payload: path, q_length, ts

article_read

separates landed-from-clicked from actually-read

Trigger: reader scrolls ≥50% of a guide (once per page view) · payload: path, ts

Compliance gate (runs on every build)

  • Disclosure strip present above <main> on every page + footer repeat — exact §5 wording (OA §5).
  • Every amazon.com anchor carries rel="sponsored nofollow" (Google); every CTA carries tag=shopnow047c-20.
  • Every data-table row links to an official source; blanks carry an unverified tag.
  • Internal links resolve; sitemap covers every page; feed contains every guide; search index covers every page.
  • No conflict markers, unfinished-work markers, or unresolved placeholders in shipped HTML.

API policy checks follow the Operating Agreement (Special Links §1, disclosure §5) and Program Policies (formatted-link requirement). The one-partner test (one link per product) remains gated on Q-04 — this build does not run it because it requires the enrolled Associates account.

Search Console checklist (owner action, FLG-008)

  1. Decide the canonical domain (Q-07) — default is the github.io project URL.
  2. Add the property in Search Console and verify ownership (DNS/HTML file/meta — token not available to this build).
  3. Submit https://sassnarep3-star.github.io/WinA/sitemap.xml.
  4. After the first query report, choose the next guide from measured queries (SG-18).
