Measurement spec

Click and conversion measurement is designed in and shipped with the site — privacy-preserving, first-party, and fail-closed. Turning it on needs one owner action (gate G-6): deploy the endpoint.

Status

Client layer: shipped (assets/js/analytics.js) · Endpoint: ready to deploy (analytics/worker.js, steps in analytics/README.md) · Current behavior: fail-closed — with no endpoint configured, events queue in the browser (max 50) and nothing is transmitted. Do Not Track / Global Privacy Control disables sending entirely.

Note on the brief: "the five defined events" was referenced without a supplied canonical list, so the five events below were defined here and frozen into code — an owner override is tracked as Q-15/FLG-008 in the registers.

The five defined events. Everything else is dropped by the endpoint allowlist.
EventFires whenPayload fieldsAnswers
1. page_view Every page load ts, sid, path, title Does anyone arrive? Which pages hold them?
2. outbound_click A sponsored/affiliate link is clicked (privacy-preserving outbound-click counter) ts, sid, path, target_host, asin, placement Which products and placements earn real clicks?
3. disclosure_view The top disclosure strip first enters the viewport ts, sid, path Do readers actually see the disclosure (FTC conspicuity evidence)?
4. guide_read A reader reaches 50% scroll depth on a guide ts, sid, path, guide Which questions engage real readers?
5. signup_intent The launch-list form is submitted ts, sid, path, email_domain (never the address) Is reader capture worth building out (S-07)?

Privacy design (enforced in code)

  • No cookies; session id is random, sessionStorage-only.
  • No IP addresses or user agents stored server-side; country code only.
  • No query strings, no form values (email domain only on signup_intent).
  • All requests go to our own endpoint — no third parties.
  • DNT/GPC honored; endpoint unset = nothing leaves the browser.

Because this claim appears on every footer, changing the analytics design requires updating the disclosure text too — the compliance checker enforces the pairing.

Endpoint contract

POST /api/collect with the event JSON; allowlist of five events; 400 on anything else. CORS limited to the site origin. Records append to daily JSONL buckets in Workers KV. Full deploy steps: analytics/README.md.

Owner action O-3: deploy, then set <meta name="cc-endpoint" content="…"> in each page head (currently present but empty). Until then the site works normally and counts nothing.

Search Console hook (SG-28)

The site is a single indexable origin (https://sassnarep3-star.github.io/WinA/) with sitemap.xml, robots.txt, canonical tags and RSS shipped. To learn which queries bring real visitors (the brief's "choose topics from measured queries"), verify the property in Google Search Console and add the HTML-tag verification token to the page heads — that token is the one thing this project cannot generate for you. Once verified, submit sitemap.xml and review the Performance report weekly; feed findings into the Q-12 row.
