Flagged for review

Everything this site could not confirm

This page is not a disclaimer and not a to-do list for a future author. It is the working surface: what was checked, what failed, and the shortest route to closing each item. A reader is entitled to know that a buying guide has gaps, and a site that cannot say where it is unsure has no business recommending anything.

2 blocking items, 3 high, 6 medium, 2 recorded as by-design. Rows are never deleted here — clear one and it gets a resolution note instead of a vanished history.

Blocking — nothing monetizable until these clear

FLG-001

All five submitted product IDs are 9 characters; an ASIN is 10

blocking Monetization open

What was found
B04G1MEwY, B02NbDxp3, B00hJ57DV, B0c8moW59, B0f3GKalj — each exactly 9 characters. Amazon defines an ASIN as “a unique 10-character alphanumeric code”, typically starting “B0”.
Why it matters
No listing can be cited, priced, described, or linked. Every product field in the register is blank by policy, not by omission.
How to clear it
Re-copy each ID from the product page URL (the ten characters after /dp/) or use the Associates link builder, then replace the values in data/products.json and data/product-intent.json and run npm run check.
Sources for the check
Amazon — Understanding ASINs
FLG-002

link.amazon is not an Amazon product host and carries no tag parameter

blocking Monetization open

What was found
Product pages live at https://www.amazon.com/dp/<ASIN>; Associates tagging is a `tag=` parameter inside that link (Policy §2(a): the Associates ID must appear “as a parameter in the URL of each link”). The submitted URLs have neither.
Why it matters
Even if the ID were well-formed, the supplied form could not be shown to attribute a click to the account, and it could not be reviewed for policy compliance.
How to clear it
Rebuild the five links inside Associates Central so the tag is embedded, then run the Link-Checker step in SG-05 before scaling to the rest of the catalogue.
Sources for the check
Amazon — Associates Program Policies · Amazon — tagged product links (Help)

High

FLG-006

GitHub Pages cannot run the click endpoint or hold account credentials

high Measurement open

What was found
Pages serves committed static files. A counting endpoint and a PA-API caller both need a server and a secret store, which this host does not provide.
Why it matters
The measurement layer ships as a tested local reference implementation plus the runbook for the host decision (Q-09). No page on this site claims that analytics are live.
How to clear it
Pick a runtime (small VPS, a worker platform, or a self-hosted Umami), point the site's data-collect-url at it, and keep the Associates credential server-side only.
Sources for the check
GitHub Docs — configuring a publishing source
FLG-010

Bylines are a desk byline, not a person

high Trust open

What was found
Guides are drafted with AI assistance and edited here. Inventing a credentialed human reviewer would be a fabricated endorsement — squarely inside what the FTC's honesty principle covers.
Why it matters
Every article prints an honest authorship note and states that no product was tested. The page that would normally carry the byline is /editorial-standards/.
How to clear it
Name a real, consenting human editor, add their bio and review scope to data/people.json, and change config.brand.byline.
Sources for the check
FTC — Endorsement Guides honesty principle
FLG-013

Publishing under a github.io sub-directory vs a domain you own

high Monetization open

What was found
Amazon's review criteria state plainly: “You must own your website.” A site at user.github.io/repo sits inside somebody else's domain, which is a foreseeable reason for an application to be rejected — and a rejection cannot be re-assessed for that application.
Why it matters
The site is fully built so it can be deployed to a domain you control with a one-line config change; the Pages URL is treated as a staging surface, not the application asset.
How to clear it
Buy the domain, add a CNAME + custom domain in Pages settings, set config.baseUrl, rebuild, and submit that URL to Associates Central.
Sources for the check
Amazon — application review process · GitHub Docs — custom domains for Pages

FLG-004

The niche (air fryers / multi-function kitchen appliances) is inferred from the editorial hypotheses, not from the listings

medium Editorial open

What was found
The brief's working titles concern air fryers and multi-function appliances. No submitted link resolves to a product, so no link confirms the cluster.
Why it matters
Section pages publish the buyer frameworks and hold the five intake records as pending rather than filing products into sections they may not belong to.
How to clear it
Confirm the five product titles, then set each product's category in data/products.json; the build files them automatically.
Sources for the check
Internal finding — nothing external to cite, and no external claim depends on it.
FLG-005

No demand data behind any headline

medium Findability open

What was found
Titles such as “Basket or oven-style air fryer: what should you compare?” are editorial hypotheses. There is no search-volume, click-through, or ranking data in this repository to justify a popularity claim.
Why it matters
Copy never says “popular”, “trending”, or “most searched”. The topic-selection tool (tools/next-topics.mjs) stays empty until a Search Console export is dropped into data/exports/.
How to clear it
Verify the property in Search Console, publish for two weeks, export the Queries report, and re-run npm run topics.
Sources for the check
Google — Search Console sitemaps & reports
FLG-009

Brand name “The Preheat” is not cleared

medium Brand open

What was found
No trademark or collision search was run. The name also has to stay clear of Amazon's mark usage rules — the site must not imply Amazon sponsorship (Operating Agreement §5).
Why it matters
The name is a working title used consistently across the build so it can be swapped in one file if it must change.
How to clear it
Search USPTO TESS and a general web search for the name in the publishing/review space; if clear, register the domain and update config/site.config.json.
Sources for the check
USPTO trademark search
FLG-011

Imagery is generated editorial illustration, not product photography or test photos

medium Brand open

What was found
The site's illustrations were made for this build. They are not photographs of the submitted products and are not documentation of a test kitchen.
Why it matters
Captions say what the picture is, and no image is presented as evidence that a product was used. Product imagery from Amazon's Program Content may only be used under the license Amazon supplies (Program Content, OA §1).
How to clear it
Either keep illustrations labelled as illustrations, or shoot your own photos of the product in your kitchen — which is also the single biggest trust upgrade available (SG-16).
Sources for the check
Amazon — Operating Agreement (Program Content)
FLG-012

Quoted policy text carries a revision date that must be re-checked at every publish

medium Compliance open

What was found
The Operating Agreement read here is dated “Updated: October 15, 2025”. Section numbering differs across locales (the Amazon.in agreement puts the same disclosure clause at §10), so section numbers are cited with their locale.
Why it matters
The gate stores the retrieval date with every quotation; a stale quote is a compliance bug, not a typo.
How to clear it
Re-run node tools/compliance-gate.mjs --refresh-sources monthly; it re-checks each row in data/sources.json against the live page.
Sources for the check
Amazon — Operating Agreement (US, dated Oct 15 2025) · Amazon — Operating Agreement (IN, different numbering)
FLG-015

No contact address, no privacy policy commitment, no newsletter storage decision

medium Operations open

What was found
config.contact.email is unset, and the reader-capture form in SG-30 has nowhere lawful-and-configured to send addresses. A publication that collects emails without a stated policy is worse than one that collects nothing.
Why it matters
The signup block ships as a disabled component with a visible “not wired” note. No form on this site transmits anything.
How to clear it
Add a monitored address, choose where addresses are stored, publish a privacy page naming that processor, then set config.contact.email and flip data/forms.json enabled=true.
Sources for the check
Amazon — Operating Agreement §4 warranties (compliance with applicable law)

Open questions

FLG-003

Compliance status of the supplied short links is unresolved — do not call them invalid

open question Compliance needs review

What was found
The brief asks that these links not be declared invalid. Nothing here can see where they redirect, so the honest state is unknown: not valid, not invalid, unobserved.
Why it matters
Any copy that asserted either way would be a fabrication. The site therefore prints “not observed” and leaves the redirect field empty rather than inferring a destination.
How to clear it
Open one link logged out, in a clean browser profile, record the final URL in the observation block of data/product-intent.json, and note the date. That single step moves the row from unobserved to evidence.
Sources for the check
Amazon — Associates Program Operating Agreement §1

How an item gets on this page

  3. If nothing confirms the value, the field stays blank and the data validator requires a flag ID on the row.
  4. The flag states the check that was run, so the next reader does not repeat it — and so clearing it is a task, not an archaeology project.
